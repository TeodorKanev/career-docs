Every request to the Knowledge Base API must be authenticated using an API key. The API uses Bearer token authentication — you include your key in the `Authorization` header of each HTTP request. Without a valid key, all requests return a `401 Unauthorized` error. API keys are scoped to your account and inherit the permissions of the user who generated them.

<Warning>
  Your API key grants full access to your knowledge base on behalf of your account. Never share it publicly, log it, or expose it in client-side code. If a key is compromised, revoke it immediately from your dashboard and generate a new one.
</Warning>

## Generate an API Key

To create a new API key:

1. Log in to your Knowledge Base dashboard.
2. Navigate to **Settings** → **API Keys**.
3. Click **Generate New Key**.
4. Give the key a descriptive label (e.g., `production-integration` or `ci-pipeline`).
5. Copy the key immediately — it is only shown once at creation time.

You can generate multiple keys for different integrations and revoke them individually at any time from the same **API Keys** settings page.

## Pass Your API Key

Include your API key as a Bearer token in the `Authorization` header of every request:

```bash
curl https://api.knowledgebase.io/v1/articles \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

The `Content-Type: application/json` header is required on all requests that send a JSON body (POST, PUT). For GET and DELETE requests, you only need the `Authorization` header.

## API Key Best Practices

Protecting your API key is your responsibility. Follow these practices to keep your account secure:

- **Never commit keys to source control.** A key pushed to a public repository should be considered compromised immediately — revoke it and generate a new one.
- **Use environment variables.** Store your key in an environment variable rather than hardcoding it in your application code.
- **Rotate keys regularly.** Periodically generate new keys and retire old ones, especially after team member changes.
- **Use one key per integration.** Separate keys for separate services make it easy to revoke access to a single integration without affecting others.
- **Restrict access by role.** Only generate keys from accounts with the minimum permissions needed for the integration.

## Using Environment Variables

The recommended way to use your API key is to store it in an environment variable and reference it in your requests:

```bash
export KB_API_KEY="your_api_key_here"
```

Once the variable is set, reference it in your curl commands or application code:

```bash
curl https://api.knowledgebase.io/v1/articles \
  -H "Authorization: Bearer $KB_API_KEY"
```

In application code, read the key from the environment rather than hardcoding it:

```javascript
const apiKey = process.env.KB_API_KEY;

const response = await fetch("https://api.knowledgebase.io/v1/articles", {
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
});
```

## Authentication Error Responses

If your request cannot be authenticated or authorized, the API returns one of the following errors.

**401 Unauthorized** — Returned when the `Authorization` header is missing, malformed, or contains an invalid or revoked API key.

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid or missing API key. Include a valid Bearer token in the Authorization header.",
    "status": 401
  }
}
```

**403 Forbidden** — Returned when your API key is valid but the associated account does not have permission to perform the requested action (for example, a viewer-role key attempting to delete an article).

```json
{
  "error": {
    "code": "forbidden",
    "message": "Your API key does not have permission to perform this action.",
    "status": 403
  }
}
```

If you receive a `403` error, check that the account tied to your API key has the appropriate role for the operation you are attempting. See the [Users API](/api/users) for details on roles and permissions.
